# Codex Menu Meter 2.0.0

> [!IMPORTANT]
> **本 APP 由 Claude Fable 5.2 及 GPT6 Astra 开发完成。**

开发者：**Jerry Wong** · 版本日期：**2026-11-23**

2.0.0 主要更新 Token 活动：Codex 压缩过的旧会话也计入统计，用量按天存在本机，可以看 90 天和 1 年。另外新增本周额度去向、到点提醒、新版本提示、价格表自动更新、复制诊断信息，Kimi / GLM 的 API Key 改存到钥匙串。桌面面板和手机页面改用同一份卡片代码，两边显示一致。1.1.x 的内容见 [1.1.1 发布记录](RELEASE-1.1.1.md)。

## 主要更新

### 统计更完整

- **Codex 压缩会话计入统计**：会话闲置一段时间后，Codex 会把它压缩成 `.jsonl.zst` 并删掉原文件，以前的版本读不到这些压缩文件。在开发者本机上，近 30 天的 Codex 用量因此少算了约八成。现在压缩文件分块边读边解压，几百 MB 的会话也不会整个读进内存。解析结果缓存在本机，下次启动不用再解压一遍。
- **用量按天存档，自动补回旧记录**：
  - 每天的用量汇总存在本机 `token-daily.json`，最多保留 800 天。
  - 首次启动约 20 秒后，应用在后台把磁盘上现有的旧日志读一遍，补回以前的记录（先 Codex 后 Claude），之后只增量更新。补记录期间面板照常使用。
- **90 天 / 1 年视图**：Token 活动的切换按钮增加「90 天」（按周）和「1 年」（按月）。柱子按模型分色；桌面上悬停、手机上点按柱子，可以看每段的明细。
- **环比**：「近 N 天已使用」旁边显示和前一段同样长的时间相比多用或少用了多少（↑ / ↓ 百分比）。前一段的记录不完整时不显示。
- **按当前价格重算**：存档只记各类 token 的用量，等价费用按当前价格表计算，价格表更新后旧日子的费用也跟着变。

### 额度去向（估算）

- 点开额度标题行的明细按钮后，两张额度卡下面会多出「额度去向 · 本周」一块。
- 它列出本周用量最多的两个项目，其余项目合成一行「其他 N 个」。每行给出约占一周额度的百分比和 API 等价费用，标题行写着「1% ≈ $X · Y token」。
- 这是按 Mac 本地日志的 API 等价费用折算的估算，不包括网页版和其他设备上的用量。本周用量太少时只显示一句说明。

### 提醒与更新

- **重置卡到期提醒**：重置卡过期前 3 天和前 1 天各发一次通知。
- **周额度重置前提醒**：离周额度重置还有 12 小时、额度还剩 20% 以上时提醒一次，没用完的额度不会留到下周。以上两项提醒都在设置里，默认开启，可以分别关掉。
- **新版本提示**：
  - 每 12 小时查一次 GitHub Releases，发现新版本时只通知一次，点通知会打开下载页。
  - 设置里新增「更新」一栏，可以立即检查。
  - 应用只提示，不会自己下载或安装。这项检查可以关掉。
- **价格表自动更新**：每天从 LiteLLM 的公开价格表取一次最新价格，取不到时用内置价格。设置里会显示当前价格的来源、日期和型号数。这项更新可以关掉。

### 设置与隐私

- **复制诊断信息**：设置里点一下，就能复制版本、系统、各开关状态、各数据来源的状态和错误码，反馈问题时直接贴上。复制的内容不含用量数字、密钥、推送地址和账号。
- **Kimi / GLM 的 API Key 改存到钥匙串**：以前存在本机的设置文件里。升级后首次启动时，应用会自动把 Key 存进 macOS 钥匙串，存成功后才从设置文件里删掉。设置里的输入框留空表示不修改，也可以一键清除。用环境变量提供 Key 的方式照旧可用。

### 界面

- **明细按钮悬停才显示**：额度标题行右侧的明细按钮平时看不见，指针移到额度区域（标题行和卡片）上才出现，用键盘把焦点移到按钮上时也会显示。按钮隐藏时位置仍然留着，标题行不会跳动。手机触屏上按钮一直显示。
- **展开后宽度不再变化**：以前展开明细时，面板会冒出滚动条，内容整体变窄 8px。现在滚动条有固定的位置，展开、收起或切换平台时，卡片宽度都不变。
- **GPT 和 Claude 展开后一样高**：以前读写量超过一千万时，额度卡明细里「读写 … 命中 …」这一行会折成两行，Claude 的面板比 GPT 高 19px，切换平台时窗口高度会跳。现在中文和英文界面里，数值再长也排得下一行。
- **缓存命中率换了分色标准**：97% 及以上显示绿色，93%–97% 显示黄色，93% 以下显示红色（以前的分界是 99% 和 95%）。按以前的标准，97%–98% 这样已经很高的命中率也显示黄色。判色仍以显示出来的一位小数为准，桌面和手机一致，命中率旁的说明文字也已同步。
- **桌面和手机共用卡片代码**：Token 活动卡（四种时间范围、柱状图、明细）和额度去向，两端由同一份代码生成，样式和数字一致。
- README 换上了 2.0.0 的截图，用的是合成的演示数据。

### 开发

- 新增 GitHub Actions：每次推送都会在 Ubuntu 上跑语法检查和单元测试，再在 macOS 上打包 Apple Silicon 版应用，并启动它做一次冒烟测试。
- 新增 `scripts/smoke-test.sh`：用一个单独的数据目录启动打包好的应用，等它写出第一份完整状态。
- 新增 `scripts/make-demo-state.js`：生成截图用的合成演示数据。

## 下载与安装

- Intel：`Codex-Menu-Meter-macOS26-Intel-2.0.0.dmg`
- Apple Silicon（M 系列）：`Codex-Menu-Meter-macOS26-AppleSilicon-2.0.0.dmg`

先退出旧版，再把 DMG 里的应用拖进「应用程序」文件夹覆盖安装，然后重新打开，本机设置会保留。升级后首次启动，应用会在后台读一遍旧日志来补回以前的记录，这时内存占用会短暂升高。在开发者本机上，这一步大约用了一分半钟。

安装包使用 ad-hoc 签名，没有经过 Apple 公证。首次打开时，可能需要在 macOS「隐私与安全性」里允许打开。

## 验证情况

- 127 项单元测试全部通过，JavaScript 语法检查通过。另外在 UTC、洛杉矶、基里蒂马蒂三个时区下各跑了一遍测试，也模拟 Linux 平台跑过一遍，都通过。
- 用本机真实日志测了从零开始补记录的过程：约 86 秒补完，期间主进程内存最高 430 MB。之后再启动，内存最高 361 MB，稳定后约 214 MB；1.1.1 对应的两个数是 336 MB 和 173 MB。多出的部分来自这次新计入的 Codex 压缩会话。
- 桌面面板：
  - 用合成数据截图核对了 GPT 和 Claude、四种时间范围、明细收起和展开，共 16 种组合：收起时都是 522，展开时都是 714，两张额度卡都是 185 宽，都没有溢出。
  - 用真实数据核对，展开后 GPT 和 Claude 也一样高。
  - 深色外观、按钮悬停才显示、强制出现滚动条时宽度不变，都检查过。
  - 在真实面板窗口里反复展开、收起，两个平台的宽度都没有变。
- 手机页面：在 390×844、375×667、320×568 三种屏幕尺寸下，GPT 和 Claude 的四种时间范围都在一屏内。和 1.1.1 的截图逐像素对比，只有这次有意修改的地方不同。用鼠标时按钮悬停才出现，触屏上一直显示。
- 价格表自动更新实际取到了 135 个型号的价格；新版本检查能读到 GitHub 上的最新版本，并且会带上 ETag，减少重复下载；复制出来的诊断信息里没有用量、密钥和账号。
- 模拟 CI 的环境（用户目录为空、数据目录单独）启动应用，23 秒写出完整状态，补记录也走完了。打好的 Intel 版在同样的环境里用 `scripts/smoke-test.sh` 跑，26 秒通过。
- 打包：两个 DMG 中的应用都通过 `codesign --verify --deep --strict`，主程序分别为 x86_64 和 arm64，Touch Bar helper 和面板原生模块都含双架构；安装包里的 `src/` 和仓库逐文件一致。
- 在开发者本机从 1.1.1 覆盖安装：首次启动约 88 秒补完记录（Codex 存了 68 天，Claude 存了 32 天），期间主进程内存最高约 400 MB，补完后回落到约 190 MB。启动约 45 秒后取到 135 个型号的价格；新版本检查读到的最新版本是 1.1.1，没有误报。
- API Key 迁移用一个测试 Key 试过：写进钥匙串后，设置文件里的才删掉；钥匙串不可用时，Key 留在设置文件里照常使用。开发者本机没有配置 Kimi / GLM，真实 Key 的迁移没有试过。
- 只在 Intel Mac 上安装运行过，Apple Silicon 版没有在实机上验证。日文界面里，额度卡明细的「読み書き … ヒット …」这一行仍然放不下，会折成两行；GPT 和 Claude 都这样，所以两边一样高。
